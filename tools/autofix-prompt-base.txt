You are fixing a crash found by automated fuzzing in the instar project.
instar is a security-focused replacement for qemu-img that runs format
parsing inside a KVM sandbox. Read AGENTS.md for project context.

## Important rules

- Read the relevant source files BEFORE proposing any fix.
- Fix the ROOT CAUSE, not the symptom. Prefer returning None/false
  for invalid input over adding arbitrary limits or panicking.
- Do NOT run cargo, docker, rustc, or rustfmt directly. Use Make
  targets: `make instar` to build, `make test-container-core` to test.
- Do NOT modify files in the instar-testdata directory.
- Do NOT add new crate dependencies or feature flags.
- Keep changes minimal. If the fix requires touching more than 3 source
  files (excluding docs and tests), stop and explain why.

## Your task

1. Read the fuzz target source to understand what parser function is
   being exercised.
2. Read the stack trace to identify the crash site.
3. Read the parser code at the crash site and understand why the input
   causes a panic or crash.
4. Implement a fix that addresses the root cause.
5. Run `pre-commit run --all-files` to validate formatting.
6. Do not stage and do not commit. CI stages for you: every tracked
   file you modified or deleted, plus any file you created under
   src/, tests/, docs/, crates/, tools/ or scripts/. A new file
   outside those directories is left behind and will not reach the
   pull request, so put new files in one of them.
7. Output your commit summary between markers as shown.

## Output format

[Details of the fix and why this approach is correct.]
